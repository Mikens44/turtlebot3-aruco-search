# TurtleBot3 ArUco Search

Autonomous search and localization of five ArUco-marked cubes using a TurtleBot3 Waffle robot in Gazebo. The robot uses an RGB camera to detect markers and Nav2 to navigate through a known environment.

In the final simulation experiment, the robot successfully located **all 5 cubes**, achieving a mean XY localization error of **5.8 cm**.

## Requirements

The project was developed and tested using:

- ROS 2 Jazzy
- Gazebo Harmonic
- TurtleBot3 Waffle
- Nav2
- Docker

The simulation environment, including the `arm05_sim` package, is provided separately as part of the laboratory setup and is not included in this repository.

## 1. Set Up the Docker Environment

Download the laboratory Dockerfile and build script:

```bash
wget https://raw.githubusercontent.com/kamilmlodzikowski/LabARM/main/Lab05-Problem1/Dockerfile -O Dockerfile
wget https://raw.githubusercontent.com/kamilmlodzikowski/LabARM/main/Lab05-Problem1/arm_05_build.sh
bash ./arm_05_build.sh
```

Start the container using **NVIDIA GPU acceleration**:

```bash
wget https://raw.githubusercontent.com/kamilmlodzikowski/LabARM/main/Lab05-Problem1/arm_05_run_gpu_nvidia.sh
bash ./arm_05_run_gpu_nvidia.sh
```

Alternatively, run the simulation on **CPU**:

```bash
wget https://raw.githubusercontent.com/kamilmlodzikowski/LabARM/main/Lab05-Problem1/arm_05_run_cpu.sh
bash ./arm_05_run_cpu.sh
```

These scripts are maintained in the original laboratory repository.

## 2. Prepare the Workspace

Clone this repository on the host machine:

```bash
git clone https://github.com/Mikens44/turtlebot3-aruco-search.git
cd turtlebot3-aruco-search
```

Copy the source packages into the running Docker container:

```bash
docker exec ARM_05 mkdir -p /cube_ws/src
docker cp ./src/. ARM_05:/cube_ws/src/
```

The following steps assume that the laboratory workspace is available at `/arm_ws` and the project workspace is located at `/cube_ws`.

Build the ROS 2 packages **inside the container**:

```bash
source /arm_ws/install/setup.bash
cd /cube_ws

colcon build --symlink-install
source install/setup.bash
```

> **Note:** `ARM_05` is the container name used during development. If your container has a different name, replace it in the commands above.

## 3. Launch the Simulation

Open a terminal inside the container:

```bash
source /arm_ws/install/setup.bash
ros2 launch arm05_sim world.launch.py
```

Wait until Gazebo and the navigation system have initialized.

## 4. Start the ArUco Search Nodes

Open a second terminal inside the container:

```bash
source /arm_ws/install/setup.bash
source /cube_ws/install/setup.bash

ros2 launch turtlebot3_cube_search cube_search.launch.py \
  marker_size:=0.07 \
  optical_frame:=camera_rgb_optical_frame \
  use_sim_time:=true
```

The `marker_size` parameter must match the physical size of the ArUco pattern, **not the entire cube**. In the laboratory models, the pattern measures approximately 7 cm, while the cube itself measures 9 cm.

## 5. Start the Search Mission

Open a third terminal inside the container:

```bash
source /arm_ws/install/setup.bash
source /cube_ws/install/setup.bash

ros2 action send_goal /find_cubes \
  cube_search_interfaces/action/FindCubes \
  "{timeout_sec: 6000.0}" --feedback
```

The robot will autonomously navigate between observation points, scan its surroundings, and detect ArUco markers.

Once all five unique marker IDs have been confirmed, the action finishes with `SUCCEEDED` and returns their estimated positions in the `map` coordinate frame.

## 6. Inspect the Results

Display the detected cubes and their estimated positions:

```bash
ros2 topic echo /cubes
```

Check the configured marker size:

```bash
ros2 param get /aruco_detector marker_size
```

Inspect the ground-truth cube positions generated by Gazebo:

```bash
cat /root/.ros/arm05_sim/logs/latest.txt
```

Cube positions are randomized when the simulation starts, so they may differ between runs.

## 7. Run the Tests

Inside the container:

```bash
source /arm_ws/install/setup.bash
source /cube_ws/install/setup.bash
cd /cube_ws

colcon test --packages-select cube_search_interfaces turtlebot3_cube_search
colcon test-result --verbose
```

The last automated test run completed successfully: **48 tests passed**.

## Notes

- The project requires the laboratory simulation environment, including `arm05_sim`, its map, and the Nav2 configuration.
- Make sure the previous search action has finished or has been canceled before starting another mission.
- To clear previously stored cube observations, call:

  ```bash
  ros2 service call /cube_localizer/reset std_srvs/srv/Trigger '{}'
  ```

- The project was validated in Gazebo simulation, not on a physical TurtleBot3.
- Docker is used for reproducibility, but the ROS 2 packages can also be built in a compatible native environment.

For additional configuration details and troubleshooting, see the [package documentation](src/turtlebot3_cube_search/README.md).
